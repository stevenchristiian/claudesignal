## The fund-level read is RESTORED — and the four-run diagnosis was wrong

This is the most useful infrastructure finding on this deck so far, because **the open item was mis-diagnosed
for four runs.**

- §9 recorded: *`curl` returns **403** on `/btc/`, `/eth/`, `/sol/` and `/hyp/`* and *Chromium failed every
  HTTPS request with `ERR_CERT_AUTHORITY_INVALID`*, concluding the item **needed the user**.
- **The 403 is not an egress denial and not a Farside ban.** Its 5,352-byte body is a **Cloudflare managed JS
  challenge** — `Just a moment...`, `_cf_chl_opt`, `cType: 'managed'`. `curl` cannot run the challenge script;
  a real browser can. Nothing was blocking access; the wrong client was being used.
- **Chromium's CA failure had a documented fix that had not been applied.** `/root/.ccr/README.md` says the
  browser NSS store is set up, but `/root/.pki/nssdb` was **empty** and `certutil` was **not installed**, so
  the setup step could not have run. Fix:
  ```
  apt-get install -y libnss3-tools
  certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n ccr-agent-proxy -i /root/.ccr/agent-proxy-ca.crt
  ```
  **TLS verification was never disabled and no flag weakening it was used** — the proxy's own CA was imported
  into the trust store the browser actually reads, which is exactly what the README prescribes. `example.com`
  then returned 200 and Farside cleared.
- Mechanics worth keeping: a **fresh browser context per slug** clears the challenge reliably; reusing one
  context across slugs gets a fresh challenge per page and often fails. Wait on **a table with >8 rows**, not
  on the title changing.

> **Two general rules. (1) Read the body of a 403 before classifying it. A status code names a category, not a
> cause, and a JS-challenge 403 and a policy 403 look identical to `curl -w %{http_code}`. (2) When a README
> says an accommodation is "already set up", verify the artefact it would have created.** Four runs were spent
> escalating to the user over a blocker that was two installed packages away, and the escalation was itself
> reasonable each time — what was missing was re-deriving the diagnosis instead of inheriting it. Same family
> as §5.5's "re-derive inherited claims, not only new ones", applied to an environment fact.
