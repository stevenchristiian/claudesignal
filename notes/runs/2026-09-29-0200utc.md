### Two assertions were at fault — a SIXTH consecutive harness-fault run

**Check 3** matched only **23** single-quoted fields where ~114 exist. Cause: the regex required `: '` with a
space, but the build writes catalyst and macro fields as `date:'…'`, `text:'…'`, `cls:'…'` with **no space after
the colon**. Fixed with `:\s*'`, which returns **124** — *exactly the count the 09-28 run recorded*, which is the
cheap confirmation that the assertion and not the file was wrong.
> **A second, stronger fix was added and should be kept:** the textual regex `'([^']*)'` **cannot detect the thing
> it is checking for** — a field containing an apostrophe terminates the match early, so the offending field is
> silently skipped rather than flagged. Check 3 now *also* evaluates the arrays and inspects every field JS-side
> (114 fields, 0 bad). **A regex whose delimiter is the character it is searching for is structurally blind.**
> Same family as the 09-28 `async function` extractor: a validator that can miss is worse than one that shouts.
